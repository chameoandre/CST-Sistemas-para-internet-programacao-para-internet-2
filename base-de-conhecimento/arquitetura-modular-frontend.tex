\section{Contexto e Motivação da Refatoração}\label{sec:contexto}

Durante o desenvolvimento inicial do portal unificado da disciplina de Programação para a Internet 2, o arquivo \path{index.html} concentrava tanto a marcação semântica e os modais Bootstrap 5 quanto a totalidade da lógica em JavaScript da aplicação. Tratava-se de um monólito com \textbf{mais de 5.445 linhas de código inline} contidas em uma única tag \texttt{<script>}, elevando o tamanho do documento para impressionantes 11.070 linhas.

\begin{conceito}{A Importância do Desacoplamento Pedagógico}
Em sala de aula, ensina-se aos futuros tecnólogos a separação estrita de interesses (\textit{Separation of Concerns}). A prática pedagógica é consolidada no \textbf{Roteiro Prático 04 — Arquitetura Modular com ES6 Modules}, no qual os estudantes estruturam aplicações web separando utilitários, serviços de persistência e camadas de visualização. Manter o portal da própria unidade curricular em formato monolítico criava uma contradição didática que a presente refatoração eliminou integralmente.
\end{conceito}

Esse cenário anterior gerava três ordens de desafios críticos:
\begin{enumerate}
  \item \textbf{Sobrecarga de Contexto e Degradação de Manutenção:} A adição ou correção de qualquer elemento visual (como filtros da Central de Demandas ou cartões da SNCT) exigia a inspeção de milhares de linhas, aumentando a latência das intervenções e o risco de colisões;
  \item \textbf{Acoplamento Severo com o DOM e Armazenamento:} Constantes globais, manipulação direta de \texttt{localStorage}, rotinas de OAuth2 com Google Identity Services e geradores de templates HTML compartilhavam o mesmo escopo global sem limites arquiteturais;
  \item \textbf{Dificuldade na Adição de Testes e Evolução:} Funções utilitárias como sanitização de strings contra XSS (\texttt{escapeHtml}) e formatação temporal ficavam inacessíveis para reuso isolado.
\end{enumerate}

Com a refatoração concluída em 4 fases cirúrgicas, o \path{index.html} foi reduzido em \textbf{5.448 linhas (corte de 49,2\%)}, tornando-se um arquivo estritamente declarativo, enquanto toda a inteligência da aplicação passou a operar via módulos nativos do ES6 (\path{<script type="module" src="js/app.js">}).

\subsection{Camada de Serviços e I/O (\texttt{services/})}

A persistência no navegador é completamente intermediada por \path{storageService.js}. Caso o navegador esteja em modo anônimo estrito ou com cotas esgotadas, o serviço captura as exceções e mantém a operação estável em memória:

\begin{boxCodigoJS}[js/services/storageService.js]
import { STORAGE_KEY_DEMANDAS, DEMANDAS_INICIAIS } from "../config/constants.js";

export function carregarDemandas() {
  try {
    const raw = localStorage.getItem(STORAGE_KEY_DEMANDAS);
    if (!raw) return DEMANDAS_INICIAIS;
    const lista = JSON.parse(raw);
    return Array.isArray(lista) && lista.length > 0 ? lista : DEMANDAS_INICIAIS;
  } catch (erro) {
    console.warn("Falha ao acessar LocalStorage; utilizando dados de contingência:", erro);
    return DEMANDAS_INICIAIS;
  }
}

export function salvarDemandas(demandas) {
  try {
    localStorage.setItem(STORAGE_KEY_DEMANDAS, JSON.stringify(demandas));
    return true;
  } catch (erro) {
    console.error("Erro crítico ao gravar demandas no LocalStorage:", erro);
    return false;
  }
}
\end{boxCodigoJS}

A comunicação externa com a planilha Google Sheets via Google Apps Script é centralizada em \path{apiService.js}. O método utiliza cabeçalho \texttt{text/plain;charset=utf-8} para evitar bloqueios de pré-voo CORS (\textit{CORS preflight}):

\begin{boxCodigoJS}[js/services/apiService.js]
export async function chamarApiAppsScript(acao, payload = {}) {
  const url = window.PROGWEB2_CONFIG?.appsScriptUrl;
  if (!url) throw new Error("URL da API do Google Apps Script não configurada.");

  const corpoRequisicao = JSON.stringify({ acao, ...payload, timestamp: new Date().toISOString() });

  const resposta = await fetch(url, {
    method: "POST",
    headers: { "Content-Type": "text/plain;charset=utf-8" },
    body: corpoRequisicao
  });

  if (!resposta.ok) throw new Error(`Falha na requisição HTTP: status ${resposta.status}`);
  return await resposta.json();
}
\end{boxCodigoJS}

\subsection{A Ponte de Retrocompatibilidade no \texttt{js/app.js}}

Uma das maiores inovações arquiteturais desta refatoração foi garantir que o \path{index.html} continuasse funcionando sem a necessidade de reescrever centenas de atributos de manipuladores declarativos legados (\texttt{onclick="..."} e \texttt{onchange="..."}).

\begin{conceito}{Escopo de Módulos vs. Escopo Global (\texttt{window})}
Ao carregar um script com \texttt{type="module"}, o navegador executa o código em escopo fechado. As funções definidas dentro do módulo \textbf{não existem no objeto global \texttt{window}}. Para viabilizar a transição sem quebras no HTML existente, o \path{js/app.js} expõe explicitamente as 79 funções manipuladoras ao escopo global.
\end{conceito}

\begin{boxCodigoJS}[js/app.js]
// Vinculação controlada das rotinas públicas ao objeto global window
const manipuladoresGlobais = {
  showTab, toggleTheme, alternarDestaqueCard,
  filtrarDemandas, abrirModalNovaDemanda, salvarDemandaFormulario,
  navegarParaEtapaSNCT, abrirModalInscricaoSNCT, confirmarInscricaoSNCT,
  abrirModalAvaliacaoRubrica, salvarAvaliacaoRubrica,
  iniciarLoginGoogle, efetuarLogoutGoogle, sincronizarComBackendAppsScript
  // ... mapeamento das 79 rotinas públicas necessárias
};

Object.entries(manipuladoresGlobais).forEach(([nome, funcao]) => {
  if (typeof funcao === "function") {
    window[nome] = funcao;
  }
});
\end{boxCodigoJS}

\section{Guia de Manutenção \& Métricas de Impacto}\label{sec:extensao}

\subsection{Como Adicionar uma Nova Funcionalidade ao Portal}

Para manter a integridade da arquitetura em camadas nas próximas manutenções, siga rigorosamente o fluxo de desenvolvimento abaixo:

\begin{enumerate}
  \item \textbf{Novas Constantes ou Roster:} Caso surjam novas turmas, novas chaves de cache ou novos instrumentos avaliativos, registre-os em \path{js/config/constants.js} ou \path{js/config/rubricasData.js};
  \item \textbf{Acesso a Dados:} Qualquer necessidade de consulta ou escrita em \texttt{localStorage} ou chamadas remotas de rede deve receber um método correspondente em \path{js/services/};
  \item \textbf{Renderização de Componentes:} A construção de strings HTML de cards ou tabelas pertence exclusivamente aos módulos da pasta \path{js/views/}. Use sempre \texttt{escapeHtml()} para qualquer dado digitado por usuário ou estudante;
  \item \textbf{Ponto de Conexão no DOM:} Se o novo componente demandar interação direta via atributo HTML (\texttt{onclick}), inclua a função correspondente no mapa de vinculação em \path{js/app.js}.
\end{enumerate}

\begin{atencao}{Regra de Ouro da Camada de Visualização}
Nenhum módulo da pasta \path{js/views/} deve executar diretamente comandos como \texttt{localStorage.setItem()} ou invocar \texttt{fetch()} para serviços externos. Toda a persistência deve obrigatoriamente transitar por \path{js/services/storageService.js} ou \path{js/services/apiService.js}.
\end{atencao}

\section{Checklist de Verificação Arquitetural}\label{sec:checklist}

\begin{checklist}[Checklist para validação de novas contribuições no portal]
\begin{itemize}
  \item[\caixaMarcar] \textbf{Zero scripts inline no HTML:} Nenhuma nova tag \texttt{<script>} com lógica de negócio foi adicionada ao \path{index.html}.
  \item[\caixaMarcar] \textbf{Desacoplamento do storage:} Nenhuma view executa leitura ou escrita direta no \texttt{localStorage}.
  \item[\caixaMarcar] \textbf{Sanitização contra XSS:} Todo dado dinâmico renderizado em template literals utiliza a função \texttt{escapeHtml()}.
  \item[\caixaMarcar] \textbf{Importações explícitas:} Todas as dependências entre arquivos utilizam caminhos relativos com extensão \path{.js}.
  \item[\caixaMarcar] \textbf{Ponte global registrada:} Funções chamadas por manipuladores declarativos no HTML foram exportadas em \path{js/app.js}.
  \item[\caixaMarcar] \textbf{Validação no GitHub Pages:} O portal carrega sem erros de sintaxe ou de CORS no console do navegador em produção.
\end{itemize}
\end{checklist}
