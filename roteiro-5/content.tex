\subsubsection{Pílula 1: Assincronismo e Leitura de Dados com Fetch API (GET)}

\textbf{Fundamentação Teórica:} No JavaScript tradicional, operações de rede não podem ser executadas de forma síncrona (\textit{bloqueante}), pois o navegador congelaria a interface enquanto aguardasse a resposta de outro computador. 

Por isso, o JavaScript moderno utiliza o mecanismo de \textbf{Promises} (promessas de valores futuros) manipuladas pelas palavras-chave \textbf{\texttt{async}} e \textbf{\texttt{await}}. A função global \textbf{\texttt{fetch(url)}} dispara uma requisição HTTP assíncrona. Quando a resposta do servidor chega, utilizamos o método \textbf{\texttt{await resposta.json()}} para converter o fluxo de texto HTTP em um objeto ou vetor JavaScript utilizável.

\begin{boxAtividade}[Mini-Exemplo 1: Leitura Assíncrona de Arquivo JSON com Fetch GET]
\textbf{Objetivo Prático:} Ler um vetor de serviços em formato JSON e preencher dinamicamente uma lista HTML na tela sem recarregar a página.
\end{boxAtividade}

\textbf{Passo 1.1: Criar o arquivo de dados (\texttt{mini-exemplos/01-fetch-get/dados.json}):}
\begin{boxCodigoJS}[]
[
  { "id": 1, "nome": "Maré Alta Artesanatos", "preco": 35.00 },
  { "id": 2, "nome": "Garopaba Web Studio", "preco": 150.00 },
  { "id": 3, "nome": "Pescado Fresco do Zequinha", "preco": 42.00 }
]
\end{boxCodigoJS}

\textbf{Passo 1.2: Criar a página de teste (\texttt{mini-exemplos/01-fetch-get/index.html}):}
\begin{boxCodigoHTML}
<!DOCTYPE html>
<html lang="pt-BR">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Mini-Exemplo 1: Fetch API GET</title>
  <link href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/dist/css/bootstrap.min.css" rel="stylesheet">
</head>
<body class="bg-light p-4">
  <div class="container" style="max-width: 500px;">
    <div class="card shadow-sm">
      <div class="card-body">
        <h5 class="card-title mb-3">Mini-Exemplo 1: Fetch API (GET)</h5>
        <p class="text-muted small">Carregamento assíncrono de dados com async/await.</p>
        
        <button id="btnCarregar" class="btn btn-primary w-100 mb-3">
          Carregar Serviços Locais
        </button>

        <ul id="listaServicos" class="list-group">
          <!-- Os itens serão inseridos aqui pelo JavaScript -->
        </ul>
      </div>
    </div>
  </div>

  <script>
    // 1. Mapeamento dos elementos da pagina
    const btnCarregar = document.getElementById('btnCarregar');
    const listaServicos = document.getElementById('listaServicos');

    // 2. Funcao assincrona dedicada com nome claro (facil de ler e depurar)
    async function carregarServicos() {
      try {
        // Passo 2.1: Dispara a requisicao HTTP para o arquivo
        const resposta = await fetch('dados.json');

        // Passo 2.2: Converte a resposta em formato JSON para um vetor JavaScript
        const servicos = await resposta.json();

        // Passo 2.3: Limpa a lista antes de adicionar novos elementos
        listaServicos.innerHTML = '';

        // Passo 2.4: Percorre a lista com laco for..of e cria os elementos no DOM
        for (const servico of servicos) {
          const item = document.createElement('li');
          item.className = 'list-group-item d-flex justify-content-between align-items-center';
          item.innerHTML = `
            <span>${servico.nome}</span>
            <span class="badge bg-success rounded-pill">R$ ${servico.preco.toFixed(2)}</span>
          `;
          listaServicos.appendChild(item);
        }

      } catch (erro) {
        console.error('Falha ao carregar os dados do arquivo:', erro);
      }
    }

    // 3. Vincula a funcao ao evento de clique de forma limpa e direta
    btnCarregar.addEventListener('click', carregarServicos);
  </script>
</body>
</html>
\end{boxCodigoHTML}

\subsubsection{Pílula 2: Microbackend Flask e a Política de Mesma Origem (CORS)}

\textbf{Fundamentação Teórica:} Em uma arquitetura web real, os dados não residem em arquivos estáticos locais no navegador, mas sim em um servidor backend. No Python, o microframework \textbf{Flask} permite instanciar um servidor HTTP e declarar rotas RESTful com o decorador \texttt{@app.route()}.

Entretanto, por medidas de segurança essenciais, os navegadores implementam a \textbf{Política de Mesma Origem} (\textit{Same-Origin Policy - SOP}). Como a nossa página frontend roda na porta \texttt{5500} (Live Server) e o Flask escuta na porta \texttt{5000}, o navegador bloqueia a requisição a menos que o backend declare explicitamente a liberação de \textbf{CORS} (\textit{Cross-Origin Resource Sharing}) via cabeçalho \texttt{Access-Control-Allow-Origin: *}. No Flask, utilizamos a biblioteca \textbf{\texttt{flask-cors}}.

\begin{boxAtividade}[Mini-Exemplo 2: Microservidor Flask \& Consumo Cross-Origin]
\textbf{Objetivo Prático:} Executar um microservidor Python em porta distinta e consumi-lo via Fetch a partir do navegador, compreendendo a atuação do CORS.
\end{boxAtividade}

\textbf{Passo 2.1: Criar o microservidor Python (\texttt{mini-exemplos/02-micro-flask-cors/server.py}):}
\begin{boxCodigoPY}
from flask import Flask, jsonify
from flask_cors import CORS

app = Flask(__name__)
# Habilita o CORS para permitir requisições de outras origens (Live Server na porta 5500)
CORS(app)

@app.route('/api/status', methods=['GET'])
def obter_status():
    return jsonify({
        "status": "online",
        "servidor": "Micro API Flask",
        "cidade": "Garopaba - SC"
    })

if __name__ == '__main__':
    app.run(port=5000, debug=True)
\end{boxCodigoPY}

\subsubsection{Pílula 3: Envio de Dados via POST (JSON.stringify e Headers HTTP)}

\textbf{Fundamentação Teórica:} Enquanto requisições \texttt{GET} apenas solicitam dados sem alterar o estado do servidor, o verbo \textbf{\texttt{POST}} envia um payload de dados no corpo (\textit{Body}) da mensagem HTTP para criação de novos registros (\textit{Create}).

Ao utilizar a Fetch API para enviar dados com \texttt{POST}, três parâmetros de configuração são \textbf{rigorosamente obrigatórios}:
\begin{enumerate}[leftmargin=*]
  \item \textbf{\texttt{method: 'POST'}:} Especifica o verbo HTTP de envio;
  \item \textbf{\texttt{headers: \{ 'Content-Type': 'application/json' \}}:} Informa ao servidor que o corpo da mensagem trafega estruturado em formato JSON;
  \item \textbf{\texttt{body: JSON.stringify(objeto)}:} Converte o objeto JavaScript em uma cadeia de caracteres de texto compatível com o protocolo HTTP.
\end{enumerate}
No servidor Flask, o payload é recebido e decodificado automaticamente com o método \textbf{\texttt{request.get\_json()}}.

\begin{boxAtividade}[Mini-Exemplo 3: Cadastro de Serviço via Fetch POST]
\textbf{Objetivo Prático:} Enviar dados de um formulário via POST em formato JSON para o Flask e receber confirmação com status HTTP 201 Created.
\end{boxAtividade}

\textbf{Passo 3.1: Criar o servidor com rota POST (\texttt{mini-exemplos/03-fetch-post/server.py}):}
\begin{boxCodigoPY}
from flask import Flask, jsonify, request
from flask_cors import CORS

app = Flask(__name__)
CORS(app)

servicos_cadastrados = []

@app.route('/api/cadastrar', methods=['POST'])
def cadastrar_servico():
    dados = request.get_json()
    if not dados or 'nome' not in dados or 'preco' not in dados:
        return jsonify({"erro": "Campos obrigatórios ausentes."}), 400

    novo_id = len(servicos_cadastrados) + 1
    registro = {
        "id": novo_id,
        "nome": dados['nome'],
        "preco": float(dados['preco'])
    }
    servicos_cadastrados.append(registro)
    print(f"[API FLASK] Novo servico cadastrado: {registro}")

    return jsonify({
        "mensagem": "Servico cadastrado com sucesso no servidor!",
        "registro": registro,
        "total": len(servicos_cadastrados)
    }), 201

if __name__ == '__main__':
    app.run(port=5000, debug=True)
\end{boxCodigoPY}

\textbf{Passo 3.2: Criar o formulário frontend (\texttt{mini-exemplos/03-fetch-post/index.html}):}
\begin{boxCodigoHTML}
<!DOCTYPE html>
<html lang="pt-BR">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Mini-Exemplo 3: Fetch API POST</title>
  <link href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/dist/css/bootstrap.min.css" rel="stylesheet">
</head>
<body class="bg-light p-4">
  <div class="container" style="max-width: 500px;">
    <div class="card shadow-sm">
      <div class="card-body">
        <h5 class="card-title mb-3">Mini-Exemplo 3: Fetch API (POST)</h5>
        <p class="text-muted small">Enviando dados estruturados em JSON via requisição POST.</p>
        
        <form id="formCadastro">
          <div class="mb-3">
            <label for="campoNome" class="form-label">Nome do Serviço:</label>
            <input type="text" id="campoNome" class="form-control" placeholder="Ex: Conserto de Pranchas" required>
          </div>

          <div class="mb-3">
            <label for="campoPreco" class="form-label">Preço Base (R$):</label>
            <input type="number" id="campoPreco" class="form-control" step="0.01" placeholder="Ex: 80.00" required>
          </div>

          <button type="submit" class="btn btn-success w-100 mb-3">
            Enviar via POST para a API
          </button>
        </form>

        <div id="feedbackPost" class="alert alert-secondary d-none mb-0"></div>
      </div>
    </div>
  </div>

  <script>
    // 1. Mapeamento dos elementos do formulario
    const formCadastro = document.getElementById('formCadastro');
    const campoNome = document.getElementById('campoNome');
    const campoPreco = document.getElementById('campoPreco');
    const feedbackPost = document.getElementById('feedbackPost');

    // 2. Funcao assincrona nomeada para processar o envio
    async function cadastrarNovoServico(evento) {
      evento.preventDefault();

      const dadosParaEnvio = {
        nome: campoNome.value.trim(),
        preco: parseFloat(campoPreco.value)
      };

      try {
        const resposta = await fetch('http://127.0.0.1:5000/api/cadastrar', {
          method: 'POST',
          headers: {
            'Content-Type': 'application/json'
          },
          body: JSON.stringify(dadosParaEnvio)
        });

        // Validacao explicita sem contracoes
        if (resposta.ok === false) {
          throw new Error(`O servidor retornou codigo de erro: ${resposta.status}`);
        }

        const dadosResposta = await resposta.json();

        feedbackPost.className = 'alert alert-success mb-0';
        feedbackPost.classList.remove('d-none');
        feedbackPost.innerHTML = `
          <strong>${dadosResposta.mensagem}</strong><br>
          <small>ID gerado: #${dadosResposta.registro.id} | Total no servidor: ${dadosResposta.total}</small>
        `;

        formCadastro.reset();

      } catch (erro) {
        feedbackPost.className = 'alert alert-danger mb-0';
        feedbackPost.classList.remove('d-none');
        feedbackPost.innerHTML = `<strong>Falha ao enviar:</strong> ${erro.message}`;
      }
    }

    // 3. Vincula o evento submit a funcao
    formCadastro.addEventListener('submit', cadastrarNovoServico);
  </script>
</body>
</html>
\end{boxCodigoHTML}

\subsubsection{Pílula 4: Resiliência de Rede e Feedback Visual (try/catch/finally com Spinner)}

\textbf{Fundamentação Teórica:} Em aplicações de produção, falhas de conectividade (servidor fora do ar, oscilação de Wi-Fi, erro 500) são inevitáveis. Uma aplicação de qualidade profissional precisa:
\begin{itemize}[leftmargin=*]
  \item Interceptar erros de rede com blocos \textbf{\texttt{try...catch}};
  \item Validar o status HTTP com a propriedade booleana \textbf{\texttt{resposta.ok}} (que retorna \texttt{true} apenas para códigos HTTP 200–299);
  \item Fornecer feedback visual instantâneo durante a espera (\textbf{Spinner de Carregamento} do Bootstrap);
  \item Utilizar obrigatoriamente o bloco \textbf{\texttt{finally}}, que é executado \textbf{sempre} (tanto em caso de sucesso quanto de falha), garantindo que o spinner seja ocultado e o botão reativado.
\end{itemize}

export async function obterServicos() {
  try {
    const resposta = await fetch(`${API_BASE_URL}/servicos`, {
      method: 'GET',

      signal: AbortSignal.timeout(3000)

\textbf{Responsabilidade Arquitetural:} Coordenar os fluxos de eventos da interface utilizando \texttt{await} para aguardar a persistência no banco remoto antes de fechar modais e atualizar a vitrine.
\end{boxAtividade}

\begin{boxCodigoJS}
// js/main.js
import {
  obterServicos,
  salvarServico,
  removerServico,
  testarConexaoApi,
  estaConectadoNaApi
} from './services/vitrineService.js';

import {
  renderizarCards,
  exibirSpinner,
  atualizarStatusConexao,
  exibirToast
} from './views/vitrineView.js';

document.addEventListener('DOMContentLoaded', async () => {
  const form = document.getElementById('formCadastro');
  const container = document.getElementById('vitrineContainer');
  const filtroCategoria = document.getElementById('filtroCategoria');
  const contadorEl = document.getElementById('totalServicosBadge');
  const statusApiBadge = document.getElementById('statusApiBadge');
  const modalEl = document.getElementById('modalCadastro');
  const btnSalvarTexto = document.getElementById('btnSalvarTexto');
  const btnSalvar = document.getElementById('btnSalvar');

  let cacheServicosAtuais = [];

  async function atualizarInterface() {
    exibirSpinner(container);
    const conectado = await testarConexaoApi();
    atualizarStatusConexao(conectado, statusApiBadge);

    cacheServicosAtuais = await obterServicos();
    const categoriaSelecionada = filtroCategoria ? filtroCategoria.value : 'todas';
    const servicosFiltrados = categoriaSelecionada === 'todas'
      ? cacheServicosAtuais
      : cacheServicosAtuais.filter(s => s.categoria === categoriaSelecionada);

    renderizarCards(servicosFiltrados, container);
    if (contadorEl) {
      contadorEl.innerText = `${cacheServicosAtuais.length} Serviços Cadastrados`;
    }
  }

  if (filtroCategoria) {
    filtroCategoria.addEventListener('change', () => {
      const categoria = filtroCategoria.value;
      const filtrados = categoria === 'todas'
        ? cacheServicosAtuais
        : cacheServicosAtuais.filter(s => s.categoria === categoria);
      renderizarCards(filtrados, container);
    });
  }

  // Inicialização assíncrona
  await atualizarInterface();

  // Reset do formulário ao abrir modal
  if (modalEl) {
    modalEl.addEventListener('show.bs.modal', () => {
      form.reset();
      form.classList.remove('was-validated');
    });
  }

  function obterValorCampo(idCampo) {
    const elemento = document.getElementById(idCampo);
    if (elemento) {
      return elemento.value.trim();
    }
    return '';
  }

  // Cadastro de Novo Serviço via HTTP POST (Função Nomeada)
  async function cadastrarNovoServico(evento) {
    evento.preventDefault();
    if (form.checkValidity() === false) {
      evento.stopPropagation();
      form.classList.add('was-validated');
      return;
    }

    const dados = {
      nome: obterValorCampo('nome'),
      categoria: document.getElementById('categoria').value,
      bairro: obterValorCampo('bairro'),
      precoBase: parseFloat(obterValorCampo('precoBase')) || 0,
      telefone: obterValorCampo('telefone'),
      descricao: obterValorCampo('descricao')
    };

    if (btnSalvar) btnSalvar.disabled = true;
    if (btnSalvarTexto) btnSalvarTexto.innerText = 'Gravando...';

    try {
      await salvarServico(dados);
      let msg = 'Serviço salvo localmente (Modo Offline).';
      if (estaConectadoNaApi() === true) {
        msg = 'Serviço gravado no banco de dados SQLite!';
      }
      exibirToast(msg, 'success');

      const modal = bootstrap.Modal.getOrCreateInstance(modalEl);
      modal.hide();
      await atualizarInterface();
    } catch (erro) {
      exibirToast('Erro ao processar cadastro.', 'danger');
    } finally {
      if (btnSalvar) btnSalvar.disabled = false;
      if (btnSalvarTexto) btnSalvarTexto.innerText = 'Salvar no Banco';
    }
  }

  form.addEventListener('submit', cadastrarNovoServico);

  // Exclusão Assíncrona via HTTP DELETE (Função Nomeada)
  async function tratarExclusaoNaVitrine(evento) {
    const btnExcluir = evento.target.closest('.btn-excluir');
    if (btnExcluir) {
      const id = btnExcluir.getAttribute('data-id');
      if (confirm('Deseja realmente remover este serviço da vitrine?')) {
        await removerServico(id);
        await atualizarInterface();
        exibirToast('Serviço excluído da vitrine.', 'warning');
      }
    }
  }

  container.addEventListener('click', tratarExclusaoNaVitrine);
});
\end{boxCodigoJS}

\begin{boxAtividade}[{Fase 6/6: Verificação de Integração \& Prova de Contingência}]
\textbf{Responsabilidade Arquitetural:} Executar o roteiro de testes em dois cenários: com a API online no laboratório e com o servidor desligado comprovando a resiliência offline.
\end{boxAtividade}

\textbf{1. Teste Conectado (API Online):}
\begin{itemize}[leftmargin=*]
  \item Inicie o backend com \texttt{python app.py} na porta \texttt{5000};
  \item Abra o frontend via Live Server (\texttt{http://127.0.0.1:5500/index.html});
  \item O badge no topo deve exibir: \textbf{\textit{Backend Online (Flask + SQLite)}};
  \item Cadastre um novo serviço e observe a requisição HTTP POST sendo logada no terminal do Flask!
\end{itemize}

\textbf{2. Teste de Resiliência (Fallback LocalStorage):}
\begin{itemize}[leftmargin=*]
  \item No terminal do Flask, pressione \texttt{Ctrl + C} para desligar o servidor;
  \item Recarregue a página no navegador com \texttt{F5};
  \item O frontend detecta a indisponibilidade e muda o badge para: \textbf{\textit{Modo Offline (LocalStorage)}};
  \item Os cards continuam aparecendo normalmente a partir da cópia em cache!
\end{itemize}

A aplicação demonstrou sucesso na comunicação assíncrona cliente-servidor via Fetch API, realizou persistência no SQLite e provou resiliência arquitetural ao operar em modo de contingência offline.
\end{boxTeste}
